# Per-memory-type calibration dataset + ECE measurement

**Blueprint refs:** FR-6 (confidence & abstention) · §16 (ECE ≤ 0.05) · OQ4
**Reconciliation:** `docs/CODEX-RECONCILIATION.md` §4 — FR-6
("the conformal calibration thresholds need a real per-memory-type calibration set
\+ tuning to reach §16's ≤0.05. The completion line provides the calibration
harness; Codex tunes the thresholds.")

This directory is that harness. It is **net-new, eval-only** — it never imports or
mutates `src/mnemosyne`. It drives the engine exclusively through the public CLI
(`mneme capture` / `mneme search` / `mneme calibration-tune`) via the existing
`eval/harness/cli_driver.py` seam, exactly like the §33 harness.

## Files

| File | What it is |
|------|------------|
| `dataset.py` | The labeled calibration set: a per-memory-type corpus + probes labeled `answerable`/`unanswerable` with gold substrings. Spans 5 memory types: `fact`, `episodic`, `preference`, `procedural`, `relation`. Single source of truth. |
| `dataset.json` | Frozen JSON snapshot of `dataset.py` (for non-Python consumers / Codex's tuner). Regenerated by the runner. |
| `runner.py` | Drives the real engine, collects **real** confidence + abstention, derives correctness from **real** hits, computes ECE + reliability table + Brier — under both the policy-default and the installed conformal threshold. |
| `report.json` | Latest run output: headline ECE, per-type ECE, reliability diagram, abstention quality, the confidence-signal root-cause diagnostic, and the Codex handoff. |
| `test_calibration_eval.py` | Pytest: dataset shape + a slow end-to-end run asserting real, well-formed numbers and the handoff structure. |
| `conftest.py` | Registers the `slow` marker (dir-local). |

## How `correct` is measured (not fabricated)

Confidence comes from the engine; correctness is derived from the engine's **own**
retrieved hits matched against the dataset's gold substrings:

```
answerable   & not abstained & gold substring in a hit  -> correct
answerable   & abstained                                -> incorrect (missed)
unanswerable & abstained                                -> correct  (good abstain)
unanswerable & not abstained                            -> incorrect (false accept)
```

No synthetic confidences are injected — this is what makes the ECE "real".

## Codex reconciliation handoff

`report.json -> codex_reconciliation.calibration_examples[<memory_type>]` is the
exact `[{confidence, correct}]` list `mneme calibration-tune --memory-type <mt>`
consumes. The workflow remains:

1. Re-run `runner.py` after retrieval/confidence changes.
2. Codex tunes per-type conformal thresholds / `target_coverage` against those
   lists (minimise `ece.policy_threshold` while keeping `false_accept_rate` in
   bound).
3. Re-run `runner.py` to re-measure ECE the same way.

The dataset, labels, and harness are stable across all of this: only the engine's
confidence signal changes, and the measurement re-runs unchanged.

## What is intentionally adversarial

Each memory type carries `clear` and `near` answerable probes plus `hard-negative`
unanswerable probes (lexically close, semantically absent) and one `poison` probe
(a prompt-injection string used as an unanswerable item — **inert data, never
obeyed**; it exists only to confirm the engine abstains/down-weights it). The
calibration gap lives at the decision boundary, so the set is dense there.
