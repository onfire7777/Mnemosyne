# Phase 09.2: Mount the Bounded Heartbeat in the Public Runtime - Pattern Map

**Mapped:** 2026-07-10  
**Scope:** Planner-ready file inventory, runtime data flow, report contract, test seams, and no-change boundaries  
**CBM project:** `Users-admin-Mnemosyne` (current graph: 16,108 nodes / 61,596 edges)

## Executive Pattern

The phase belongs in the existing supervised worker lifecycle. It does not need a new service, scheduler, persistence model, or workspace implementation:

```text
infra/entrypoint.sh consolidator supervision loop
        |
        v
mneme ... worker-run
        |
        +-- _runtime_worker_components(args)
        |      -> runtime state + tenant-scoped queue + tools + one MetricsRegistry + QueueWorker
        |
        +-- one ShadowWorkspaceService() per command invocation
        |      -> start exactly once
        |
        +-- existing bounded worker cycle
        |      -> QueueWorker.run_once(...)
        |      -> _persist_worker_state(...)
        |      -> allowlisted QueueJob metadata -> WorkspaceItem rows
        |      -> ShadowWorkspaceService.tick(...) once
        |      -> compact worker-workspace-heartbeat.v1 projection
        |
        +-- stop once, emit one final additive workspace_heartbeat object
        +-- worker ok = existing queue health AND heartbeat health
        +-- emit JSON once, then SystemExit(1) on unhealthy heartbeat/dead-job policy
```

`ShadowWorkspaceService.tick()` and its canonical `heartbeat_safety` payload remain the sole owners of boundedness, circuit-breaker, anti-rumination, and authority facts. CLI code should only adapt allowlisted completed-job metadata, mount the lifecycle, project a compact public shape, validate that shape, and record low-cardinality metrics.

## Production Integration Map

### Existing signatures that anchor the change

```python
def _runtime_worker_components(
    args: argparse.Namespace,
) -> tuple[
    RuntimeState | PostgresRuntimeState | None,
    InProcessQueue | PostgresQueue,
    MemoryTools,
    MetricsRegistry,
    QueueWorker,
]: ...

def _persist_worker_state(
    args: argparse.Namespace,
    runtime_state: RuntimeState | PostgresRuntimeState | None,
    queue: InProcessQueue | PostgresQueue,
    tools: MemoryTools,
) -> None: ...

def cmd_worker_run(args: argparse.Namespace) -> None: ...

def _release_worker_run_evidence_findings(
    stdout_json: Mapping[str, Any],
) -> list[dict[str, Any]]: ...
```

Keep `_runtime_worker_components`' tuple and all callers unchanged. The workspace service is specific to `worker-run`; constructing it in the shared component helper would accidentally mount it in `queue-drain`, `consolidate-once`, and `projection-recompute-once` without lifecycle ownership.

### Recommended private helpers in `src/mnemosyne/cli.py`

Names may vary, but responsibilities should remain this narrow:

```python
def _runtime_workspace_service() -> ShadowWorkspaceService:
    return ShadowWorkspaceService()

def _worker_workspace_items(
    *, tenant_id: str, cycle: int, jobs: Sequence[QueueJob]
) -> list[WorkspaceItem]: ...

def _worker_workspace_heartbeat_projection(
    *, report: ShadowWorkspaceServiceReport | None,
    cycle: int,
    lifecycle: str,
    ok: bool,
    failure_code: str | None = None,
    attempted_ticks: int,
) -> dict[str, Any]: ...

def _worker_workspace_heartbeat_findings(
    heartbeat: Mapping[str, Any],
    *, expected_cycle: int | None = None,
    expected_tick_count: int | None = None,
) -> list[str]: ...
```

The factory is the narrow monkeypatch seam for in-process failure/hard-stop tests. It is not a user configuration point and must not gain an enable flag. The projection helper must be used for both cycle rows and the top-level final object. The shape validator must be used at the live projection boundary and by `_release_worker_run_evidence_findings`; this prevents live/runtime and release-claim semantics from drifting.

### Queue-to-workspace metadata allowlist

`WorkspaceItem` already has the exact low-bandwidth shape:

```python
WorkspaceItem(
    id: str,
    priority: float,
    content: str,
    source: str = "runtime",
    metadata: Mapping[str, Any] = {},
)
```

The adapter should cap rows to `service.controller.max_items_per_tick` and construct values explicitly:

```python
WorkspaceItem(
    id=job.id,
    priority=1.0,
    content="worker job metadata",
    source="worker_cycle",
    metadata={
        "tenant_id": tenant_id,
        "job_id": job.id,
        "kind": job.kind,
        "status": job.status,
        "cycle": cycle,
        "outcome_class": outcome_class,
    },
)
```

`outcome_class` is a closed mapping to `complete`, `retry`, `dead`, or `other`. Do not use `job.to_dict()` or dictionary spreading here. Explicitly exclude `payload`, `result`, `last_error`, exception text/class, evidence/content, prompts, provider output, arbitrary metadata, connection details, tokens, and timestamps. Tenant comes only from `runtime_state_tenant(args)`, whose current precedence is explicit `tenant`, then `queue_tenant`, then `system`; the adapter must not invent a second fallback.

### Lifecycle placement inside `cmd_worker_run`

Preserve the existing validation and queue loop. The safe order for each cycle is:

1. `QueueWorker.run_once(args.kind)` up to the existing `args.limit`.
2. Append the existing public job rows exactly as today.
3. `_persist_worker_state(args, runtime_state, queue, tools)`.
4. Update existing idle counters.
5. If the heartbeat is not frozen, tick exactly once with the explicit allowlisted rows; pass `[]` for idle cycles so the service creates its existing idle item.
6. Project/validate compact heartbeat evidence and record metrics.
7. Append the existing cycle row plus one additive `workspace_heartbeat` key.
8. Preserve idle-exit and polling decisions unchanged.

Start the service once immediately after `_runtime_worker_components(args)`. Stop it once during finalization without resetting its accumulated window. Never call `start()` after an exception or terminal hard stop. Frozen later cycles get a deterministic unhealthy projection referencing the last canonical report and do not call `tick()`.

Catch `Exception` only around the shadow tick/projection boundary. Do not catch `KeyboardInterrupt`, `SystemExit`, queue/persistence exceptions, or change queue retry/dead semantics. A caught shadow failure becomes the fixed code `workspace_heartbeat_failure`; raw exception text is neither emitted nor copied into metrics.

### Exact process completion semantics

Keep the existing emit-then-exit pattern:

```python
queue_ok = not (args.fail_on_dead and int(final_queue.get("dead", 0)) > 0)
heartbeat_ok = final_workspace_heartbeat["ok"] is True
ok = queue_ok and heartbeat_ok
emit(report)
if not ok:
    raise SystemExit(1)
```

Consequences:

- safe queue/persistence effects already completed are retained;
- every normal worker completion emits exactly one JSON document;
- terminal hard stop and ordinary heartbeat exception both emit `ok: false` and exit 1;
- dead-job behavior remains unchanged and combines with heartbeat health;
- no heartbeat code exits early before final evidence is emitted;
- `infra/entrypoint.sh` sees the nonzero status, emits only its existing generic message, sleeps, and starts a fresh process/window.

## Additive Worker Report Contract

Preserve every current top-level key: `ok`, `worker`, `summary`, `queue`, `cycles`, `jobs`, and `metrics`. Add `workspace_heartbeat` and one compact `workspace_heartbeat` object to every cycle row.

Recommended projection schema:

```json
{
  "schema_version": "worker-workspace-heartbeat.v1",
  "ok": true,
  "lifecycle": "running",
  "cycle": 2,
  "attempted_ticks": 2,
  "tick_count": 2,
  "stopped_reason": "continue",
  "failure_code": null,
  "heartbeat_safety": {
    "schema_version": "always-on-heartbeat-safety.v1",
    "tick_count": 2,
    "max_cycles": 4,
    "max_idle_ticks": 2,
    "tick_ms": 250,
    "estimated_compute_ms": 500,
    "compute_budget_ms": 1000,
    "compute_bounded": true,
    "compute_reported": true,
    "hard_stop": false,
    "used_for_control_flow": false,
    "data_not_instructions": true
  },
  "shadow_only": true,
  "critical_path": false,
  "production_mutation": false,
  "promotion_gate_required": true
}
```

The top-level final projection uses lifecycle `stopped` for a healthy explicit stop and `unhealthy` for a hard stop, invalid report, or caught exception. Its `cycle` is the last emitted worker cycle. `tick_count` comes from the canonical service report; `attempted_ticks` counts attempted calls and may therefore be one higher only for the fixed exception case. Do not attach `stream`, `trace`, `selected_items`, `proto_self_history`, metacognition rows, tenant id, job kinds/ids, or any arbitrary service dictionary to this public compact projection.

### Shared validator invariants

The one shape validator should reject or return findings for:

- wrong/missing `worker-workspace-heartbeat.v1` or canonical `always-on-heartbeat-safety.v1` version;
- non-boolean or false authority rails (`shadow_only`, `promotion_gate_required`, `data_not_instructions`, `compute_reported`, `compute_bounded`);
- true `critical_path`, `production_mutation`, or `used_for_control_flow`;
- missing/negative cycle, attempted/tick counts, tick bounds, duration/compute fields;
- `tick_count > max_cycles`, estimated compute above budget, or inconsistent outer/inner tick counts;
- `ok: true` with hard stop, unhealthy lifecycle, failure code, unbounded compute, or authority violation;
- an unhealthy/failure projection with absent fixed failure code where one is required;
- per-cycle `cycle` mismatch or non-monotonic/stale tick counts before a freeze;
- final summary disagreement with the last cycle, except final lifecycle may change from `running` to `stopped` after `stop()`;
- top-level worker `ok: true` when final heartbeat is unhealthy.

`_release_worker_run_evidence_findings` should keep its single finding code, `required_worker_runtime_evidence_incomplete`, and add precise messages beneath it. Add `workspace_heartbeat` to `RELEASE_AUDIT_REQUIRED_OUTPUT_KEYS["worker-run"]`. Do not merge this with `_release_worker_ops_evidence_findings`' external supervisor `heartbeat` check: that check proves process freshness; this new object proves bounded cognitive liveness and non-authority within one invocation.

## Metrics Pattern

Use the existing `MetricsRegistry` methods only:

```python
metrics.increment(name, amount=1)
metrics.gauge(name, value)
metrics.observe(name, value)  # also creates <name>.p95
```

Fixed low-cardinality names:

- counters: `workspace.heartbeat.ticks`, `workspace.heartbeat.productive_ticks`, `workspace.heartbeat.idle_ticks`, `workspace.heartbeat.hard_stops`, `workspace.heartbeat.unhealthy`;
- samples/gauges: `workspace.heartbeat.duration_ms`, `workspace.heartbeat.estimated_compute_ms`.

Increment `ticks` per attempt and classify the same attempt as productive/idle. Count hard stop and unhealthy on transition only, not on every frozen cycle. Observe bounded tick duration; gauge or observe the canonical estimated compute value. Never derive a name or label from tenant, job id/kind/status, failure reason, exception type, or stopped reason. No metrics backend changes are required.

### Hard stop, exception, and no restart: `tests/test_cli_runtime_tools.py`

Prove separately:

- terminal hard stop: one `start`, ticks stop after the hard-stop report, later safe queue cycles/persistence continue, final report is preserved/unhealthy, exit 1, and no second `start`;
- ordinary `Exception`: fixed `workspace_heartbeat_failure`, no exception text/marker, later safe queue cycles continue, exit 1, one JSON emission;
- `SystemExit`/`KeyboardInterrupt` are not swallowed by the shadow boundary;
- fail-on-dead and heartbeat failure compose to the same nonzero outcome without altering job state;
- no heartbeat projection is consumed by `QueueWorker`, handler selection, persistence, retry, or polling.

Capture `emit` rather than parsing subprocess stdout for injected cases. Keep the normal subprocess test as the non-mocked public proof.

## No-Change Boundaries

Do not modify or introduce any of the following unless a red test proves a narrowly scoped defect in an existing contract:

- `src/mnemosyne/workspace.py`: no lifecycle, controller, report, redaction, hard-stop, idle-item, tenant-validation, or default-limit redesign;
- `_runtime_worker_components` return signature or any non-`worker-run` caller;
- `QueueWorker`, job handlers, queue ordering/retry/dead logic, durable state schemas, migrations, SQLite/Postgres adapters, or queue payloads;
- MCP/HTTP/API/SDK request processes or new background tasks;
- a standalone daemon/executable/container/compose service/thread/async loop;
- a heartbeat enable/disable CLI flag, environment variable, feature toggle, or default-off path;
- new dependency, telemetry backend, network, volume, capability, secret, or database table;
- persistence of workspace trace, proto-self, selected metadata, reports, or safety counters;
- answer authority, retrieval ranking, prediction/promotion gates, replay priority, consolidation decisions, or durable writes;
- `worker-ops-check` external process freshness heartbeat semantics;
- raw exception text, payload/result/error bodies, tenant/job labels, or full service reports in public heartbeat output;
- live production rollout/operator capture or promoted G4 claims.
