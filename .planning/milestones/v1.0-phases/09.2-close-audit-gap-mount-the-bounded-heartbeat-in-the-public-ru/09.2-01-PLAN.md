# Phase 09.2 Plan 01: Mount the Bounded Public-Runtime Heartbeat

<objective>
Close the v1.0 runtime-mount audit gap by hosting one existing bounded
`ShadowWorkspaceService` inside each public `worker-run` invocation, ticking it
once per existing productive or idle cycle with metadata-only input, and
publishing additive evidence that proves liveness, bounded compute,
non-authority, and visible unhealthy failure. Preserve every queue outcome and
the existing production consolidator topology.
</objective>

<execution_context>
Execute as one atomic Wave 1 TDD plan. Follow Ponytail: reuse the existing
service, worker loop, metrics registry, JSON report, release validator, and
supervisor; add only private helpers in `cli.py`, a comment-only entrypoint
clarification, and focused tests. Add no dependency, daemon, thread, toggle,
workspace component redesign, persistence model, or transport. Use systematic
debugging: prove the absent public contract red first, mount the minimum shared
root-cause fix, then run focused, Phase 7/G0, full, security, review, CBM,
gbrain, git, and exact-SHA CI gates.
</execution_context>

<threat_model id="T-09.2-01" standard="ASVS-L1" block_on="high">
  <boundary>Tenant-scoped queue state crosses a new metadata projection into an in-process shadow workspace, then a compact safety projection crosses the public worker JSON, metrics, release evidence, and production supervisor boundary.</boundary>
  <assets>Tenant isolation, queue payload/result/error confidentiality, durable queue correctness, worker availability, promotion and mutation authority, release-attestation integrity, bounded CPU/memory, and operator-visible failure state.</assets>
  <risks>
    <risk severity="high">Tenant mixup binds a job or heartbeat to a different tenant or a global fallback despite an explicit runtime tenant.</risk>
    <risk severity="high">Raw payloads, results, error text, evidence, prompts, provider output, secrets, connection data, or arbitrary metadata leak through workspace items, public JSON, metrics, logs, or release evidence.</risk>
    <risk severity="high">Adversarial job metadata becomes a prompt/control instruction rather than bounded data.</risk>
    <risk severity="high">Shadow output gains authority over queue selection, retry/dead state, persistence, polling, promotion, retrieval, replay, or durable mutation.</risk>
    <risk severity="high">Silent heartbeat loss hides a hard stop or exception, repeatedly retries it, resets safety through an in-process restart, or reports the invocation healthy.</risk>
    <risk severity="high">Queue interference or data loss changes cadence, duplicates or drops jobs, reorders persistence, or alters fail-on-dead behavior.</risk>
    <risk severity="high">Tenant/job-derived metric names or unbounded items enable cardinality, memory, or compute denial of service.</risk>
    <risk severity="high">Release evidence claims a mounted, bounded, non-authoritative heartbeat when cycle evidence is missing, stale, malformed, contradictory, or forged by weak invariants.</risk>
  </risks>
  <controls>
    <control>Resolve tenant only through the existing runtime/queue tenant helper and construct capped `WorkspaceItem` objects field by field from a closed metadata allowlist.</control>
    <control>Use fixed content/source strings and a closed outcome class; never spread or serialize a job object, payload, result, exception, arbitrary metadata, or workspace stream into the heartbeat surface.</control>
    <control>Retain and validate `data_not_instructions`, `shadow_only`, `critical_path=false`, `production_mutation=false`, `used_for_control_flow=false`, and `promotion_gate_required=true` on every compact projection.</control>
    <control>Start once, tick at most once per existing cycle, cap rows by the existing controller limit, freeze on hard stop/failure, stop once, and never call `start()` again within the invocation.</control>
    <control>Catch only `Exception` around the shadow tick/projection boundary; never swallow `KeyboardInterrupt`, `SystemExit`, or queue/persistence failures. Emit a fixed failure code without exception text.</control>
    <control>Run and persist queue work before the advisory tick, never feed its output back into worker control, and preserve the existing idle, polling, retry, dead, and fail-on-dead paths byte-for-byte except additive reporting.</control>
    <control>Use fixed low-cardinality metric names and canonical bounded numeric fields; never derive labels or names from tenant, job, status, reason, or exception data.</control>
    <control>Use one validator for live cycle/final projections and release evidence; reject schema, monotonicity, bounds, lifecycle, authority, worker-ok, and final-cycle inconsistencies.</control>
  </controls>
  <verification>Block implementation or completion on any high finding, cross-tenant input, raw-data marker leak, control-path dependency, in-process restart, queue outcome drift, unbounded metric/item behavior, silent unhealthy outcome, or release claim accepted without complete consistent proof.</verification>
</threat_model>
