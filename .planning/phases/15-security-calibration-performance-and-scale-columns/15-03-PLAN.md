# Phase 15 Plan 03: S4 Performance, Scale, and Resource Closure

## Contract and admission

**Goal:** Freeze the CAP-006 measurement ABI for warm/concurrent P95, provider
selection, production backfill, and 100k behavior, plus the separate CAP-011
physical 8 GiB compact grounded-QA acceptance boundary.

**Prerequisites:** S2 and S3 implementation/evidence plans are merged in order;
the S4 plan is approved; a fresh Worktrunk lane is based on current
`origin/main`; live writers and exact leases are disjoint. Measurement requires
the applicable hardware/operator admission, immutable candidate SHA, pinned
dataset/provider/model/runtime identities, and a quiesced host. Physical 8 GiB
work additionally requires the existing compact source path and both native
x86-64 AVX2 Windows and Linux hosts.

**Consumes:** `eval/latency/bench.py`, `eval/latency_warm/bench_warm.py`,
`eval/provider_bakeoff/run.py`, Postgres vector-hygiene/backfill observations,
the committed retrieval baselines, result-v2 resource-receipt identity, compact
reader/reranker/provider parity, `HARDWARE-WORKLOAD-PREFLIGHT.md`, and
`COMPACT-MODEL-8GB-ACCEPTANCE.md`.

**Produces:** content-addressed warm and concurrent latency distributions; a
provider comparison/default decision; 100k and null-embedding-backfill receipts;
and separate physical Windows/Linux 8 GiB acceptance receipts. Each receipt
binds the exact candidate, workload, SUT boundary, resource profile, raw
artifacts, abort status, and result digest.

**Non-goals:** No asserted benchmark number, after-the-fact threshold, provider
promotion from smoke evidence, production backfill without operator authority,
official/public result, protected attempt, hardware emulation as physical proof,
quality downgrade, or ML dependency in Python core.

## Measurement ABI and immutable gates

Every retained receipt records:

- repository SHA and clean-tree state; command/arguments; UTC and monotonic
  start/end; host OS/build/kernel, architecture, CPU flags, accelerator and
  runtime versions; dataset, fixture, config, model, tokenizer, provider,
  container/image, schema, and result-contract digests;
- SUT boundary and all included processes, containers, databases, proxies,
  caches, indexes, filesystems, and background workers; worker/model-request
  count; cold/warm state; warmup; repetitions; concurrency; timeouts; retries;
- total/free/available memory before and during the run, memory pressure,
  swap/pagefile before/after, process-tree RSS plus platform PSS/working set,
  VRAM where applicable, disk/index growth, network bytes, load averages, CPU
  seconds, wall time, and the first abort condition;
- per-operation observations, successes, timeouts, errors, excluded samples
  with reasons, P50/P95/P99, throughput, sample count, confidence interval, and
  raw-artifact hashes. Failed requests remain in denominators.

The canonical fast-path target and budgets still unresolved by Section 15 remain
targets, not achieved facts. This plan does not invent missing numeric gates.
Deep mode is reported separately and is not forced through the fast-path gate.
Approximate/vector changes must retain the committed recall/nDCG tolerance;
CAP-003 still requires both QA thresholds, deterministic-retrieval
non-regression, grounding, positive graph/PPR evidence, and custody.

For the physical 8 GiB profile, the existing proposed ceilings remain unchanged:
model/tokenizer artifacts at most 1 GiB, compact-sidecar peak memory at most
3 GiB, whole Mnemosyne process tree at most 6.5 GiB, and at least 1.5 GiB
system-available memory throughout. Any OOM, swap/pagefile growth prohibited by
the runbook, pressure throttling, deadline breach, missing process, hidden
worker, or receipt mismatch fails the run.

## Dependency order and future exact leases

These leases are frozen for later admission; this plan commit authorizes no code
or measurement. One integration owner audits live writers before admission and
again before merge.

1. `15-03-01` freezes the common latency receipt and must land first.
2. `15-03-02` provider evidence and `15-03-03` scale/backfill evidence may run
   in parallel only for deterministic harness work. Their measured runs are
   serialized by the one-measured-worker gate.
3. `15-03-04` starts only after compact parity and exact-scale development
   evidence are clean and physical hosts pass admission.
4. `15-03-05` is the sole integration/evidence owner and follows every admitted
   predecessor. Missing external evidence remains blocked, not waived.

  pinned compact artifacts, unchanged quality/custody, human operator.
