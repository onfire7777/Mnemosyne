# Phase 15 Plan 01: S2 Capability Upgrades

## Contract and admission

**Goal:** Deliver CAP-007 and CAP-008 as minimal extensions of the current
memory substrate, and produce the bounded CAP-009 cartridge A/B and go/no-go
artifact without adding a model dependency to core.

**Prerequisites:** Phase 14's REPRO-001 implementation must be merged before
product code starts; this plan and its exact write leases must be approved.
The implementation owner must rebase a fresh Worktrunk worktree on current
`origin/main`, prove no active lease overlap, and preserve the completed W3
CAP-012/CAP-013 contracts.

**Consumes:** `OperatingPolicy`; `ConsolidationWorker.run_queue_payload`;
`RuntimeJobHandlers.handlers`; the existing deterministic RAPTOR hierarchy;
`MemoryEngine.retrieve(..., filt=...)`; `Evidence.valid_from/valid_to`;
access-policy expiry; prediction-error/write-priority metadata; promotion,
security, custody, erasure, mutation-budget, and regression gates.

**Produces:** a versioned cadence/sleep receipt in consolidation results; a
provenance-linked `global_sensemaking` retrieval projection; write-gate
precision/recall and sensemaking regression cells; and a cartridge A/B receipt
with an explicit `adopt`, `research-only`, or `reject` decision.

**Non-goals:** No new memory engine, scheduler service, model SDK, model weight
write, public benchmark claim, official/upstream result, held-out tuning,
hardware assertion, production rollout, or change to CAP-012/CAP-013.

## Fixed safety and evidence rules

- Existing tenant, subject, branch, trust, sensitivity, capability, provenance,
  erasure, append/supersede, and retrieved-text-is-data rails remain mandatory.
- Cadence defaults remain behavior-preserving. Sleep execution is explicit,
  asynchronous queue work with bounded items, passes, runtime, and retries; it
  fails closed on missing custody, stale identity, or authorization.
- Freshness uses existing validity/access-expiry fields. Expiry is half-open,
  monotonic, audited, and cannot be reversed by replay or clock rollback.
- Map and reduce inputs retain source CIDs and policy scope. A reduce output is
  derived evidence, never independent corroboration or authority to mutate.
- Surprise is bounded to `[0, 1]`; absent, malformed, non-finite, or untrusted
  signals cannot increase write authority. Low-surprise inputs may remain
  metadata-only but must not evade durable `must_keep` or deletion semantics.
- Development fixtures and labels stay separate from candidate inputs. A
  capability implementation is not proof of superiority: CAP rows advance only
  from their required measured evidence.
- Hardware, protected datasets, official runs, custody approvals, and operator
  production evidence remain separate gates and do not block deterministic code
  and synthetic regression work.

## Approval and external gates

- **Before code:** Phase 14 implementation merged; design/plan approval; current
  main ancestry; exact lease and active-writer audit.
- **Before measured evidence:** frozen fixtures and metric definitions; candidate
  SHA; dataset/model/judge rights; custody receipt; resource budget; operator
  approval for protected or hardware runs.
- **Before merge:** focused tests, independent review, secret/risk sweep, one
  exact-head CI full suite, all required checks and review threads clear.
- **Before any claim:** normal post-merge verification plus the exact evidence
  required by CAP-007/008/009. Development fixtures, local A/B output, or a
  working feature are not publishable benchmark proof.
