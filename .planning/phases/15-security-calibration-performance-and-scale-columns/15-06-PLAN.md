### Scoring profile

`score_profile("wmbs-m06-v1", labels, traces)` dispatches to
`_score_wmbs_m06`, placed beside `_score_wmbs_m05`.

`_score_wmbs_m06` follows the `_score_wmbs_m05` shape:

- Import `eval.public.wmbs_m06` the same way `_score_wmbs_m05` imports
  `wmbs_m05`.
- Fixture: `labels[0]["fixture"]` when that value is a dict, otherwise
  `wmbs_m06.generate_fixture(wmbs_m06.SEEDS[0])`.
- Call `wmbs_m06.score(fixture, observations)`.
- Set `measured["family"] = "whole-memory-development"`.
- Set `measured["profile"] = "wmbs-m06-v1"`.
- Set `measured["interval"]["method"] = "descriptive"`.

`wmbs_m05.score` returns no interval, so `_score_wmbs_m05` replaces `interval`
with `{"method": "descriptive"}`. `wmbs_m06.score` already returns the
descriptive finite-corpus interval (`scope`, `statistic`, `minimum`,
`maximum`, `count`). Keep those fields. Add `method` so the runner can match
`interval_method: descriptive`. Do not add Wilson, bootstrap, CI-LCB,
baseline-improvement, or non-inferiority fields.

`wmbs_m06.score` does not accept M05 provenance traces. Its observations
argument is a mapping:

```text
{
  "control": "no-memory",
  "cases": [
    {
      "case_id": "<fixture case_id>",
      "cycles": [
        {
          "operations": ["ingest", "retrieve", "answer"],
          "answer_text": "<string>"
        }
      ]
    }
  ]
}
```

Build that mapping from adapter traces. Do not pass `answer_envelope`,
`explanation`, or `provenance_status` into `wmbs_m06.score`. Each scored case
needs five cycles. `answer_text` must be a string.

### Adapter

`run_m06_consolidation_development(benchmark, cli)` clones the
`run_m05_provenance_development` CLI-required pattern.

- `system_seam` is `public-cli-subprocess`.
- If `cli is None`, raise `ValueError` with message
  `M06 consolidation development requires a live MnemoCLI` before any other
  work.
- Bind the fixture the way `_m05_bind_fixture` does. When `fixture_id`,
  `generator_id`, or `generator_version` is present, it must match the oracle
  constants. When `dataset_sha256` is a 64-hex string, it must equal
  `wmbs_m06.canonical_sha256` of the document without that key. A complete
  family × seed × five-cycle matrix goes through `wmbs_m06.validate_fixture`.
  A smaller mapping is accepted only so a unit test can prove CLI dispatch.
  The public suite always loads the committed full fixture, so that path
  validates.
- Exercise the public CLI only. Do not import product consolidation, surprise
  gating, or a private no-consolidation control. Do not add a private
  consolidation hook.
- Tip `MnemoCLI` has no `ingest` or `retrieve` method. Map the fixture
  operations onto the methods the M05 adapter already uses:
  - ingest: `capture`, then `assert_fact`, tenant `wmbs-m06-{case_id}`,
    user = the event `actor_label`
  - retrieve: `search(tenant, cycle["retrieve"]["query"])`
- Do not call `MnemoCLI.answer`. Tip `cmd_answer` requires
  `--evaluation-read-only` and then
  `CommandGroundedProvider.from_environment()`, which raises unless
  grounded-reader commands are configured. This cell admits no provider
  budget (`PROVIDER_COST_REASON` on the Stage A oracle). M05 Stage B refuses
  `mnemo answer` for the same reason. Record `answer_text` as `""` when the
  model-free CLI payload has no string answer. Never copy `gold_answer`,
  `harmful_answer`, or `no_memory_answer` into the trace.
- Each trace row carries `case_id`, `scoring_family` =
  `"whole-memory-development"`, and `cycles` of
  `{operations: ["ingest", "retrieve", "answer"], answer_text: <string>}`.
- Return `(traces, {"backend": getattr(cli, "backend", "local")})`.
