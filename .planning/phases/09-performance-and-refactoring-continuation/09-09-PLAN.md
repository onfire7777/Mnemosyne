# 09-09 Plan: Guarded Postgres Vector Backfill Apply

## Goal

Close the source-owned gap between the read-only vector backfill plan and a real
operator-runnable backfill path, without claiming production evidence.

## Scope

- Fix Postgres assertion writes so `embedding_partition='private'` generates a
  stored vector just like evidence rows do; only `none` remains non-embeddable.
- Add a bounded `PostgresEngine.vector_backfill_apply()` method that applies one
  batch of missing vectors and returns only row ids plus SHA-256 hashes.
- Add a `vector-backfill-apply` CLI command guarded by `--confirm-apply`.
- Keep raw evidence content, raw assertion statements, provider secrets, and
  production row values out of reports.

## Non-Goals

- Do not execute a production backfill from the repo.
- Do not mark vector hygiene clean without retained operator output.
- Do not change provider defaults, add halfvec/pgvectorscale, or apply the
  Postgres tuning profile.

## Verification

- Focused Postgres perf-lane tests for private assertion embedding and bounded
  assertion backfill.
- Focused CLI tests for explicit confirmation and redacted command output.
- Ruff on touched code.
- Full suite before shipping.
