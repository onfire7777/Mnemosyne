# 09-07 Plan: Postgres Vector Hygiene Ops Gate

## Goal

Close another source-owned part of Phase 09 Task 6 by making embeddable
Postgres NULL-vector backlog visible and gateable in `ops-report`, without
changing retrieval scoring, default report pass/fail behavior, or production
runtime settings.

## Scope

- Add a read-only `PostgresEngine.vector_hygiene_snapshot()` probe.
- Count embeddable evidence/assertion rows with `embedding IS NULL`.
- Count illegal vectors in the non-embeddable `none` partition.
- Include the snapshot in `build_ops_report()` and the static dashboard.
- Add `ops-report --require-clean-vector-hygiene` as an explicit operator gate.
- Add focused tests for the SQL/count contract and report gate behavior.

## Out Of Scope

- No automatic backfill mutation.
- No live production tuning application.
- No halfvec or pgvectorscale schema rollout.
- No provider default flip.
- No operator runtime-flip evidence claim.

## Acceptance

- Postgres evidence/assertion vector hygiene is visible in the ops report snapshot.
- Default reports remain non-blocking for local/non-Postgres engines.
- `--require-clean-vector-hygiene` fails unless a real Postgres hygiene probe is
  available and clean.
- The probe is read-only and tenant/branch scoped.
