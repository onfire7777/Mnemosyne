# 09-11 Plan: Provider Bake-Off Evidence Harness

## Goal

Turn the existing provider bake-off protocol into an executable evidence
harness that can summarize baseline/candidate eval reports, include
`provider-check` evidence, flag regressions, and keep promotion blocked unless
all protocol evidence is present.

## Scope

- Add a small `eval/provider_bakeoff/run.py` harness.
- Reuse retained `provider-check` output, or run `mneme provider-check` from a
  supplied provider manifest.
- Preserve raw eval JSON/Markdown reports and emit a separate bake-off summary
  envelope.
- Compare common baseline/candidate verdicts and flag candidate regressions.
- Keep local smoke fixtures unable to flip provider defaults.
- Add focused tests for complete-evidence smoke blocking and regression
  detection.

## Out Of Scope

- Running TEI, Python service, or Rust sidecar production bake-offs in this
  source slice.
- Selecting or changing provider defaults.
- Claiming production cache-hit, latency, or Tier-B operator evidence.
- Adding negative/abstention caching without an explicit provider contract.

## Acceptance

- The harness emits `mnemosyne-provider-bakeoff-report-v1`.
- Missing required evidence is surfaced explicitly.
- Smoke fixtures keep `promotion.allowed=false` even when evidence is complete.
- Candidate regressions against baseline-passing verdicts fail the report.
- Focused tests and ruff pass.
