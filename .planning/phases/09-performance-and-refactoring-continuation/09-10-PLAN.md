# 09-10 Plan: Durable HTTP Embedding Cache

## Goal

Close the source-owned provider-cache hardening slice without changing provider
defaults: make the HTTP embedding cache optionally durable, privacy-scoped,
TTL-aware, and operator-visible while preserving byte-identical vectors.

## Scope

- Reuse `HttpEmbeddingProvider`'s existing content-hash cache key.
- Add optional stdlib SQLite durable cache storage behind an explicit path.
- Include an explicit cache scope in memory and durable cache keys.
- Store only hashed provider/model/auth/text identity plus vector bytes; never
  raw text, raw URLs, or raw API keys.
- Skip durable cache reads/writes when the input text trips existing redaction
  patterns.
- Expose cache status through `provider-check` without using the cache for the
  latency probe.
- Wire CLI, env, and registry config construction consistently.

## Out Of Scope

- No provider default flip.
- No TEI/Rust sidecar bake-off decision.
- No negative/abstention cache for non-embedding providers.
- No production cache-hit-rate or latency-win claim without retained runtime
  evidence.

## Verification

- Focused provider cache tests prove durable reuse across provider instances,
  cache-scope isolation, TTL expiry, secret-like input durable-skip behavior,
  CLI flag exposure, env builder wiring, and registry config wiring.
- Ruff covers changed provider/cache, CLI, registry, and test files.
