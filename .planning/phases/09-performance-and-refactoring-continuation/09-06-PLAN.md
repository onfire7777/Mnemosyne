# 09-06 Plan: Stateless MCP Warm Bundle Reuse

## Goal

Close the source-owned part of Phase 09 Task 7 by reusing stateless MCP tool
bundles across repeated calls in the same tenant/user/session scope without
weakening durable reload semantics.

## Scope

- Add a per-server stateless tool-bundle cache.
- Key reuse by queue tenant, tenant, user, and session/source identity.
- Invalidate local and SQLite bundles when the durable store or runtime-state
  file changes.
- Preserve the existing stateful MCP path unchanged.
- Add tests for same-scope reuse and external durable-write reload.

## Out Of Scope

- No new cache configuration surface.
- No cross-process cache.
- No provider default changes.
- No operator runtime flip or production latency claim.

## Acceptance

- Repeated stateless calls in the same scope reuse `_build_tools()`.
- Calls in another tenant scope build a separate bundle.
- A warmed local reader reloads after another server writes the durable store.
- Existing stateless durable engine/runtime-state tests still pass.
