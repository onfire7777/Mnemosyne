# Phase 09 / Plan 01 - Retrieval Channel Capability Defaults

## Objective

Close the B5/§7.5 performance blueprint slice by moving retrieval channel
parallelism from a pure default-off knob to a capability-tier default. Keep the
change parity-safe: no ranking/scoring changes, no new dependency, and no new
operator burden.

## Tasks

1. Update `pipeline.parallel_channels_enabled()` so explicit
   `MNEMOSYNE_PARALLEL_CHANNELS` values remain authoritative, and absent env
   values use the resolved capability tier.
2. Update `capability.recommended_env()` so standard/native hosts recommend
   `MNEMOSYNE_PARALLEL_CHANNELS=1` while `floor` remains `0`.
3. Update regression tests for the new default policy and preserve the existing
   Local/SQLite byte-identical parallel-vs-sequential tests.
4. Refresh stale docs/codebase-map text that still says parallel channels are
   simply default off.
5. Run focused tests, lint/hygiene, CBM impact/index, gbrain sync, commit, push,
   and wait for GitHub CI.

## Verification

- `uv run pytest -q tests/test_engine_perf_lanes.py tests/test_capability.py`
- `uv run ruff check src/mnemosyne/pipeline.py src/mnemosyne/capability.py tests/test_engine_perf_lanes.py tests/test_capability.py`
- `git diff --check`
- CBM `detect_changes` or equivalent diff-impact check
- `codebase-memory-mcp cli index_repository` for `/Users/admin/Mnemosyne`
- `gbrain sync --source mnemosyne-code` or `/sync-gbrain` equivalent
- GitHub Actions green on pushed `main`

## Non-Goals

- Do not default stored-vector MMR. That can change ranking numerics and needs
  a separate bake-off and recalibration plan.
- Do not introduce async retrieval or provider I/O rewrites in this slice.
- Do not weaken production evidence/release gates.
