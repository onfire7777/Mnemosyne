## Runtime Host

| Option | Description | Selected |
|--------|-------------|----------|
| Existing `worker-run` / production consolidator | Reuse the backend-neutral worker cycle and its existing supervised production lifecycle. | ✓ |
| MCP/API process | Run background ticks in request-scoped or stateless server processes. | |
| New daemon/container | Add another executable and deployment role. | |

**Choice:** Existing `worker-run` / production consolidator.
**Rationale:** It is already the long-running background runtime and sole write/KMS authority; MCP/API lifecycles are request-scoped/stateless, while a new daemon duplicates supervision.

---

## Cadence and Hard-Stop Lifecycle

| Option | Description | Selected |
|--------|-------------|----------|
| One bounded window per worker invocation | Tick every productive/idle worker cycle; preserve terminal stop until process supervision restarts. | ✓ |
| Restart service after every hard stop | Reset counters inside the same worker process. | |
| Unbounded background loop | Add a separate thread/scheduler with no worker-cycle bound. | |

**Choice:** One bounded service window per worker invocation.
**Rationale:** Reuses existing safety limits and makes hard stops meaningful without adding a second scheduler.

---

## Privacy-Safe Tick Inputs

| Option | Description | Selected |
|--------|-------------|----------|
| Bounded job metadata | Tenant-scoped ids/kinds/status/outcomes only; no raw payload/content. | ✓ |
| Raw queue payload | Feed job content/provider output into the workspace. | |
| Synthetic-only tick | Emit a liveness pulse disconnected from real worker activity. | |

**Choice:** Bounded job metadata.
**Rationale:** Proves the real runtime is mounted while maintaining content redaction, tenant isolation, and data-not-instructions safety.

---

## Public Observability

| Option | Description | Selected |
|--------|-------------|----------|
| Structured report plus metrics | Per-cycle and final redacted safety evidence with low-cardinality metrics and release validation. | ✓ |
| Logs only | Human-readable messages without machine-checkable contract evidence. | |
| Internal state only | Run the service without surfacing proof. | |

**Choice:** Structured report plus metrics.
**Rationale:** The audit gap is about actual public-runtime integration; machine-checkable evidence must prove liveness, bounds, and non-authority.

---

## Failure Semantics

| Option | Description | Selected |
|--------|-------------|----------|
| Visible unhealthy result and supervised restart | Preserve safe queue work/reporting, return nonzero, and let existing supervision create a fresh process window. | ✓ |
| Silently continue | Hide heartbeat absence/failure behind successful queue processing. | |
| Abort before queue persistence | Make the shadow path capable of stranding otherwise safe durable work. | |

**Choice:** Visible unhealthy result and supervised restart.
**Rationale:** The workspace stays off the critical mutation path, but an “always-on” contract cannot fail invisibly.
