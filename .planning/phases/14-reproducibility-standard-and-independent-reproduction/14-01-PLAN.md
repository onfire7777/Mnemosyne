# Phase 14 Plan 01: Neutral Reproducibility Bundle Standard

<objective>
Freeze and implement REPRO-001 as the smallest additive standard that binds a
public result to everything needed to regenerate and audit it: manifests, raw
traces, configuration, build and environment fingerprints, metrics,
uncertainty intervals, integrity hashes, rights/custody/operator disclosures,
and one clean-checkout reproduction command.

The implementation starts only after N12 lands additive result-v2 dispatch and
the protected signed-publication lease is explicitly released. It reuses the
existing public bundle lifecycle, signed ledger, static renderer contracts, and
the merged M15 canonical replay output/fixture tests at
`main@e0dd41594cec890f598718160f919c13eee1e552`. It creates no parallel
benchmark lifecycle and performs no measured, official, protected, or public
run.

This plan covers REPRO-001 and preserves RAIL-003/RAIL-004. REPRO-002 is a
separate evidence package: it stays blocked until at least one
headline-eligible official result exists with pinned inputs, complete public
bundle, operator/custody approval, separate retrieval/QA columns, and disclosed
judge where applicable.
</objective>

<standard_contract>
The new `mnemosyne.reproducibility-bundle/v1` manifest is opt-in and closed:
unknown or missing fields fail. Existing `bundle-manifest.json` version 1
dispatch and output bytes remain unchanged. The additive path uses explicit
manifest-version dispatch and binds, by canonical SHA-256 references:

- the immutable result-v2 atomic attempt and any signed-ledger inclusion
  receipt, without embedding aggregates in the atomic result;
- benchmark, dataset/split, fixture, generator, adapter, scorer, baseline,
  judge/reader/model/prompt, and upstream fidelity or successor-difference
  manifests;
- raw trace inventory and trace-index digest, deterministic SUT outputs, seed
  records/retries/aborts, and the merged M15 canonical replay digest;
- canonical config, lockfile/toolchain/build inputs, candidate Git SHA, dirty
  state assertion, platform/runtime/dependency versions, locale/timezone, and
  declared environment allowlist with values limited to public non-secret
  reproducibility inputs;
- every metric's family, name, version, value, unit, numerator/denominator or
  sample count, uncertainty method and parameters, confidence level, low/high
  interval, exclusions, and missing/unsupported/failed/aborted/not-measured
  counts;
- complete file inventory with relative normalized paths, byte sizes, media
  types, canonicalization rule, and SHA-256 digests;
- software/data licenses, source revisions, redistribution rights, PII/consent
  and takedown declarations, custody class, operator identity/role, signer
  role, and disclosure state;
- exactly one argv-form, repository-root reproduction command:
  `uv run --locked mneme eval-public --reproduce-bundle BUNDLE --out-dir DEST`.

The result-v2 lineage digest names retain these exact meanings:

- `build_fingerprint = sha256(build.json)`;
- `config_digest = sha256(config.json)`;
- `bundle_digest = sha256(bundle-manifest.json)`;
- `trace_index_digest = sha256(traces.jsonl)`.

Each value hashes the exact bytes of the named manifest-owned file as stored;
there is no parsing, reserialization, newline conversion, or Unicode
normalization before hashing. The value is encoded as lowercase hexadecimal
SHA-256 with the `sha256:` prefix. Producers must therefore write any JSON
source using its own canonical-JSON contract before hashing it. Result, ledger,
M15 replay, inventory-entry, and environment/wheelhouse digests remain separate
cross-references and are not aliases for these four fields.

`track_kind` remains one of the result-v2 contract's exact official,
successor, or development values. Official records require their frozen
upstream fidelity manifest. Successor records require parent and difference
manifests. Development records remain non-publishable and non-headline.
Independent third-party reproduction is an optional separately signed receipt;
its absence does not block an otherwise operator-run claim, and its presence
does not relabel the operator or imply neutrality/certification.
</standard_contract>

<threat_model>
Trust boundaries and blocking mitigations:

- External bundle -> verifier: reject duplicate JSON keys, non-finite values,
  excessive depth/size/counts, unknown fields, symlinks, non-files, absolute or
  escaping paths, duplicate normalized paths, digest mismatches, and inventory
  drift before executing anything.
- Manifest command -> process execution: accept only the exact closed argv
  template above; never evaluate a shell string, interpolate manifest values
  into a shell, honor bundle-provided executables, or execute from inside the
  untrusted bundle directory.
- Bundle/environment -> clean checkout: use a new detached checkout of the
  bound commit, temporary HOME/cache/output roots, the declared environment
  allowlist, UTC/C locale, and no inherited credentials. Fail if the source
  commit is unavailable, the checkout is dirty, the lock is not honored, or
  the output escapes its root.
- Raw artifacts -> public output: scan for secret-like material and require
  explicit rights, license, PII/consent, takedown, custody, and operator
  declarations. Missing declarations fail; tests never use real credentials,
  protected data, signing roots, or production artifacts.
- Result/projection -> claim: validate result-v2 and all four digest meanings,
  keep official and enhanced records out of one certified projection, preserve
  safety failures as visible/non-averageable, and keep development and private
  suites non-publishable. No code path may infer headline eligibility from a
  successful reproduction alone.
- Existing history -> additive implementation: snapshot and continuously prove
  result-v1 schema/validator/ledger bytes and behavior unchanged. Any
  compatibility drift is a blocker, not a migration opportunity.

Any high/critical trust-boundary finding, digest ambiguity, execution of
untrusted shell, secret exposure, result-v1 mutation, or official/enhanced
blending blocks the PR. There is no risk-acceptance path inside this plan.
</threat_model>
