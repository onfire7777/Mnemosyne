## Nyquist Strategy

The existing archived validation files are too terse for Phases 6-9. New files
should include:

1. a frontmatter contract with phase, validation date, `nyquist_compliant`,
   `wave_0_complete`, and status;
2. one row per critical truth, the test/evidence surface, cadence, and failure
   meaning;
3. explicit current-versus-retained evidence classification;
4. a rerun command set that samples every major seam without relying only on a
   full-suite aggregate;
5. full-suite and CI gates as backstops;
6. open-boundary rows that remain `deferred` rather than being mislabeled pass.

## Minimal Implementation Choice

No runtime-code change is currently justified. Existing GSD tools can check
phase completeness, plan structure, artifacts, key links, schema drift, and
consistency. A small repository test is warranted only if the repaired
requirements/verification links can otherwise regress silently; prefer
extending an existing planning-consistency test over creating a new framework.
