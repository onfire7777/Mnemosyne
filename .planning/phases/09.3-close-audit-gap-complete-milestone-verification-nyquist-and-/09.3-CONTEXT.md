## Implementation Decisions

### Evidence truthfulness
- **D-01:** Separate current re-verification from historical execution evidence. Every reconstructed artifact identifies its verification date, evidence source, exact SHA when available, and whether the evidence is current, retained, or historical.
- **D-02:** Never infer a pass from a checked roadmap box or file existence. A requirement passes only when a runnable check or retained, integrity-verified operator artifact proves its observable truth.
- **D-03:** Preserve explicit open/non-blocking production boundaries in Phase 9 (provider selection, cache performance, vector backfill, broader wheel adoption). Traceability may mark them deferred or non-blocking; it may not silently close them.
- **D-04:** Retain Phase 6 Tier-B custody boundaries and Phase 8 source-owned versus operator-owned distinctions. Use the verified `capture-bc10` bundle only for claims it directly supports.

### Required artifact set
- **D-05:** Add milestone-grade `*-VERIFICATION.md` artifacts for Phases 6, 7, and 8, and broaden Phase 9 verification from plan 09-13 scope to full-phase scope.
- **D-06:** Add Nyquist `*-VALIDATION.md` artifacts for Phases 6-9 using the current GSD schema and executable commands. Validation documents define sampling coverage and rerun policy; they are not substitutes for verification results.
- **D-07:** Add a truthful Phase 8 summary. It must summarize the implemented source/runtime profile and the later Tier-B closure without pretending the missing historical summary existed at execution time.
- **D-08:** Repair stale contradictions in Phase 6/8/9 planning prose only when current retained evidence conclusively supersedes them. Preserve dated historical checkpoints as historical where useful.

### Requirements traceability
- **D-09:** Give every REQ-001 through REQ-018 and NFR-001 through NFR-005 one canonical phase ownership mapping in `REQUIREMENTS.md`, with a checkbox/status and links to the proving phase verification.
- **D-10:** Add GSD's exact `requirements-completed` metadata key to phase summaries only where the summary's own work directly completed those IDs. Do not spray all IDs across every summary merely to satisfy orphan detection.
- **D-11:** Verification documents contain explicit requirement-ID tables mapping each truth to code/tests/operator evidence and a pass, deferred, or blocked disposition.
- **D-12:** Use current requirement IDs as the canonical traceability vocabulary while retaining FR/OQ/spec identifiers as blueprint anchors.

### Verification and completion
- **D-13:** Run GSD consistency, phase completeness, plan structure/artifact/key-link checks, milestone audit, full tests, Ruff, exact-SHA CI, CBM freshness, gbrain sync/doctor, review, security review, and an independent verification before declaring Phase 09.3 complete.
- **D-14:** If strict GSD tooling cannot express a truthful deferred boundary, document the boundary explicitly and prefer an honest audit failure over a fabricated green result.
- **D-15:** Keep implementation minimal and documentation-centered. Add a small deterministic repository check only if no existing GSD command can protect the repaired traceability contract from regression.
- **D-16:** Use one primary owner per requirement: REQ-009 belongs to Phase 1 with Phase 2 support; REQ-011 belongs to Phase 0 with Phases 4/5 support; NFR-001 belongs to Phase 9, NFR-002 to Phase 6, NFR-003 to Phase 0, NFR-004 to Phase 6 with Phase 09.1 support, and NFR-005 to Phase 5 with Phase 7/09.2 support.
- **D-17:** Stock milestone summary discovery does not scan archived Phase 0-5 directories. Resolve them with `gsd-sdk find-phase`, extract their summaries with the GSD summary extractor, and enforce the complete join with a deterministic repository test instead of duplicating artifacts into active phase folders.
- **D-18:** Close in two immutable evidence steps: an evidence-bearing SHA receives exact-SHA CI; an independent verification commit cites it; then the final closure SHA receives exact-SHA CI and sync checks without another repository edit.

### Agent discretion
- Exact ownership phase for requirements spanning multiple phases, provided one canonical owner and all supporting phases are named.
- Whether Phase 8 uses one aggregate summary or a numbered summary, provided `verify phase-completeness 08` recognizes it and the document is explicit about reconstruction.
- Exact deterministic command grouping in Nyquist validation files.

</decisions>
