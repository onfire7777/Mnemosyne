## Warnings

### WR-01: Deep/explain tests do not lock the exact nine-field context contract

**Severity:** WARNING

**Files:**

- `tests/test_access_policy_enforcement.py:475`
- `tests/test_access_policy_enforcement.py:508-509`
- `tests/test_parity_mcp.py:201-203`

**Issue:** The exact filter-shape test compares the complete canonical mapping
only for `search`; after calling `deep_search` it asserts only `role`, and the
`explain` call checks only the default-reader shape. The behavioral tests then
give `residency` and `region` the same value, so dropping or swapping either
field in `deep_search`, `explain`, or CLI dispatch would not be distinguished.
The generated-schema test likewise checks only property presence, optionality,
and the role default; it does not compare the nine fields' types and defaults.

**Impact:** A later context-plumbing or annotation regression could route the
wrong residency/region value, change a security-sensitive field type/default,
or omit a field while all Phase 09.1 tests remain green. That can produce an
incorrect allow or deny decision at the shared access-policy boundary, defeating
the phase's claimed exact semantic parity.

**Exact fix:** In
`test_caller_context_filter_shape_preserves_legacy_positions`, call both
`deep_search` and `explain` with distinct sentinel values and compare each
recorded `filt` dictionary against the complete expected canonical mapping
(without search-only trust keys). Add distinct residency-only and region-only
CLI/parser-dispatch assertions so those flags cannot mask one another. In
`test_caller_context_schema_is_optional_and_reader_defaulted`, compare the
nine extracted property schemas across all three operations and against explicit
expected types/defaults, including `break_glass=False` and null defaults.
