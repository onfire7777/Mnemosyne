# Test-Case Catalog — Correctness, Retrieval, Temporal/Update, Consolidation, Lifecycle, Erasure (`02a`)

*Concrete `T-*` cases for the evidence ledger, hybrid retrieval, belief/update/temporal, consolidation passes, lifecycle/forgetting, and erasure domains. Each case **asserts against a fixed contract** (cited `§N` / `FR-N` / `G-N`) — this lane validates behavior, it never defines policy.*

**Boundary: this doc does not redefine functional policy.** Retrieval ranking, belief-revision ops, the promotion gate, lifecycle/forgetting schedules, erasure semantics, and the invariant rails are owned by the build lanes and restated in `_CONTRACTS.md §1`. Every case here drives the system through the MCP surface (`_CONTRACTS §1.3`) and asserts an outcome; white-box L0/L1 store assertions are flagged explicitly. No thresholds are invented — they are quoted from §16/§15/§31 or marked `TBD-by-§N`. Calibration/personalization/invariant/portability/perf cases live in `02b`; all security/adversarial (`T-SEC`) cases live in `04`.

**Conventions (per `_CONTRACTS §4`).** Every case carries: `id`, `title`, `requirement(s)`, `metric(s)`, `layer (L0–L8)`, `phase (0–5)`, `interface`, Given/When/Then, `assertion`, `pass/fail`, `protected? (Y/N)`, `dataset`, and a `gating | shadow` posture (§1.12: Phases 0–3 hard-gate; Phases 4–5 diagnostic-behind-rails). Cases that refine a golden scenario back-reference `S1`–`S12`.

**Cross-doc IDs first surfaced here** (to be defined downstream): metrics `M-RECALL@K, M-NDCG@K, M-TOKEN-EFF, M-FASTP95, M-ASOF-ACC, M-AGM-CONF, M-ERASURE, M-CONTRA-CORR, M-DEDUP-EXACT, M-MERKLE-OK, M-EXPLAIN-COV, M-PROV-COMPLETE, M-CASCADE-CORR, M-CONSOL-REBUILD, M-DEMOTE-CORR, M-NODEGRADE, M-RECOMPUTE-SCOPE` (→ `01`); datasets `DS-PRIV, DS-SEED, DS-RECALL-ADV, DS-RET-LABELED, DS-SYNTH, DS-TEMPORAL, DS-CONTRA, DS-CONSOL, DS-LIFECYCLE, DS-ERASURE, DS-CORROB` (→ `03`).
