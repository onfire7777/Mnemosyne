## Existing distinctions worth preserving

These are inspected Mnemosyne capabilities, not claims that no competing system has them:

- **Groundedness separated from salience.** [Standing](../src/mnemosyne/standing.py) prevents repetition or interest from automatically granting answer authority; self-generated content is bounded below the grounded-evidence band.
- **Public reflection with answer-time evidence replay.** [MemoryTools.reflect](../src/mnemosyne/mcp_tools.py) exposes [GroundedAnswerOrchestrator.answer](../src/mnemosyne/answering.py) through Python, MCP and CLI. It reassembles evidence after generation and abstains on custody/content drift. Source spans and constrained synthesis make the output auditable; exact-source membership alone does not establish semantic entailment or overall answer quality. [Integration tests](../tests/test_reflect.py) cover local/SQLite stores, signed MCP scope binding, citations, abstention and absence of generated-memory writes.
- **Working and prospective memory.** Session-scoped items and scheduled intentions participate in the [retrieval pipeline](../src/mnemosyne/pipeline.py); [engine](../src/mnemosyne/engine.py) trigger evaluation includes provenance and explicit operating points.
- **Branching, corrections and erasure.** Local, SQLite and Postgres engines expose branches, temporal assertions and provenance-aware deletion. These deserve sustained cross-engine regression coverage.
- **BurnSkill learning.** [Skills](../src/mnemosyne/skills.py) and [frameworks](../src/mnemosyne/frameworks.py) turn imported material into versioned procedural knowledge; this should remain distinct from declarative observations and knowledge pages.

## Important limits of the comparison target

- Hindsight's `temporal_window` steers one search route; it is not a strict final date filter. Its fact token budget excludes metadata and may return one whole fact over budget. A stricter contract can be useful, but is not universally better. [Recall API](https://hindsight.vectorize.io/developer/api/recall)
- A restrictive retain mission can succeed with zero searchable facts. The source document remains stored but requires reprocessing for fact retrieval. Design observable zero-extraction outcomes and deliberate raw-source fallback. [Retain](https://hindsight.vectorize.io/developer/retain)
- Hindsight's default synthesis scope combines tags; unique per-session tags can fragment observations. Changing to a shared scope is a semantic/privacy decision, not just a dedup optimization. [Observations](https://hindsight.vectorize.io/developer/observations)
- Memory Defense is opt-in, affects future retains, and the documented open-source implementation is sensitive-data detection/redaction. It is not evidence of complete prompt-injection protection. [Memory defense](https://hindsight.vectorize.io/developer/memory-defense)
- Memlake's object-storage engine and scale claims belong to **Hindsight Enterprise**. The open-source Postgres engine must be compared separately. [Memlake announcement](https://hindsight.vectorize.io/blog/2026/10/13/memlake)

## Live PostgreSQL validation

The final 22 October follow-up completed **239 mixed live/unit tests with zero skips,
failures or errors**, including **20 live tests**, on disposable PostgreSQL
16.15. The live role check passed **9/9**. It covered source changes during
generation/publication, lease takeover and expiry, rollback, tenant/owner isolation,
readonly denial, and actual lock timeout/recovery. Providers were deterministic
fixtures and lease expiry used a controlled clock. Four additional live tests cover early source-change refresh, clean provider-free checks, backoff and concurrent version changes. [Report and receipts](../work/hindsight-comparison/postgres-live/REPORT.md).

The run exposed and repaired the missing model-delete grant, invalid external CID
handling, and redaction of valid provider-request source references. Source ownership
and privacy checks remained enforced. Publication holds SHARE locks on whole source
tables, so writers in other tenants can wait until publication ends; production throughput remains
unmeasured. These results validate tested runtime behavior, not answer quality or a
Hindsight benchmark advantage.

## Reliability follow-up

The [subsequent repair pass](../work/hindsight-comparison/reliability-followup/REPORT.md)
closes demonstrated ingestion, local persistence, PostgreSQL concurrent-update,
policy-restart and temporal-ordering defects. Ingestion now distinguishes live
storage from a returned but rejected CID; corrections and follow-up jobs require
accepted evidence. PostgreSQL metadata and privacy backfill lock the same source
row before merging, preserving concurrent updates and sensitivity. Calendar
boundaries use the appropriate local offset, repeated hours are ordered by UTC,
and requested first/last chronology survives later ranking stages.
Supported past-conversation queries now use the authorized lexical passage route
in default search even without a configured graph; explicit historical reads keep
their prior semantics.

Document replacement remains a separate feature. Legacy source identity labels
do not isolate content-addressed evidence, and permanent erasure cannot serve as
revision retirement. The next implementation needs owner-scoped document versions
and atomic segment publication, reusing existing text-hash extraction caches.
No benchmark was restarted for this follow-up.

## Prioritized delivery plan

1. **P0 — Establish a reproducible baseline and fix demonstrated failures.** Freeze corpus IDs, splits, configurations and versions. Record baseline answer accuracy, abstention, citation correctness, latency and cost. Run existing regression suites; repair failures with before/after evidence. Cover malformed dates, provider outputs and cross-engine behavior. Completion means reproducible artifacts, not a passing hand-selected example.
2. **P0 — Protect source custody during concurrent work.** Add/verify races involving erase, correct, retag, restrictive policy changes, cache reuse and background synthesis. Derived memory must not resurrect a deleted or now-private source. Exercise Local, SQLite and live Postgres where supported. Completion means negative isolation tests pass and degraded paths remain observable.
3. **P1 — Improve temporal and entity recall where measured errors justify it.** Explicit search clock/timezone controls are now implemented; extend evaluation to event intervals, dates with uncertain precision and range diversity. Evaluate contextual identity resolution and reversible merges. Preserve conversation-time queries separately from event-time questions.
4. **P1 — Make the best retrieval configuration reproducible.** Validate actual dense embeddings and neural reranking, route budgets, source expansion, semantic-neighbor recall and fallback reporting. Compare RRF/interleaving only for their intended tasks. Include route ablations and cost ceilings; avoid adding latency without a demonstrated gain.
5. **P1 — Define evolving observations as a first-class contract.** Reuse assertions, corroboration, corrections and summary infrastructure. Add stable observation identity, evidence quotes, independent-proof accounting, contradiction history, scope, freshness, dedup and explicit source invalidation. Repeated self-generated statements must not become independent proof.
6. **P2 — Extend the implemented public reflection surface.** Python, MCP and CLI now reuse the existing answer orchestrator with fixed evidence/hop limits, typed claim derivations, citation replay and factual abstention. Next evaluate the configured reader on representative user tasks, then design freeform advisory synthesis, personality/disposition controls and optional observation/mental-model-first retrieval with explicit support checks. Those behaviors are not supplied by the current quotation/deterministic-operation contract. Keep policy rules outside memory-supplied instructions and avoid automatic writeback until its source custody is specified.
7. **P2 — Extend the implemented maintained-answer lifecycle.** Private questions, source-checked answers, full refresh, stale state, CAS versions, metadata-only history, opt-in scheduled refresh and bounded change-aware polling now exist. PostgreSQL transaction-bound publication passed live concurrency/permission tests with conservative table locks; measure the cross-tenant contention cost under production load. Next add measured incremental invalidation and consolidation-triggered jobs. The current fingerprint conservatively invalidates on any readable corpus change. Add folder/Markdown projection and richer synthesis only with tested source custody; generated answers must never become independent evidence.
8. **P2 — Complete document and multimodal workflows.** Introduce append/replace source versions and delta extraction with reliable invalidation. Test ordered text/image inputs, attachment lineage, provider capability checks, encrypted/raw storage policy and deletion propagation.
9. **P3 — Prove scale and usability.** Benchmark realistic concurrent mixed workloads, restart/retry behavior and supported integrations. Treat enterprise-scale storage and ecosystem parity as independent projects rather than requirements to inflate a recall score.

## Fair benchmark and release criteria

The [controlled comparison protocol](comparison-protocol.md) records the held-out pilot,
native ingestion/recall, common Codex reader/judge, frozen configuration and failure scoring.
The owner cancelled execution during ingestion to prioritize runtime improvements.
It produced no comparison result or evidence of a ranking advantage.

- Evaluate the same benchmark version, split, question IDs, corpus, answer budget and grader for both systems. Preserve each system's native ingestion/retrieval when measuring the product; report a second controlled comparison if normalizing model backbones.
- Record reader, extractor, embedding, reranker and grader model/version, quantization, prompts, temperatures, token budgets, retrieval mode, worker count, hardware and every paid/provider dependency. A hashing fallback must never be reported as the intended embedding configuration.
- Freeze development tuning before held-out evaluation. Do not inspect or write test answers into memory, select only favorable cases, or retune against the held-out leaderboard. Retain skipped/failed question IDs and explain their scoring treatment.
- Publish per-question predictions and receipts, aggregate and category results, paired confidence intervals, abstention precision/coverage, unsupported-claim and citation-support rates, p50/p95/p99 latency, ingestion time, storage growth and total cost. Report warm/cold cache conditions separately.
- Test features that conversational QA misses: correction, contradictory reports, source deletion, expired policies, multi-tenant leakage, multilingual queries, uncertain dates, long-range retrieval and concurrent updates. Publish these as separate evaluation tracks.
- A passing unit suite demonstrates tested behavior only. A higher score on one dataset demonstrates a win on that dataset and setup only. Claim a leaderboard position only after the relevant evaluator accepts the run. Neither source review nor feature parity establishes “all bugs fixed” or “best memory in the world.”

## Suggested regression inventory

Existing starting points include [public reflection](../tests/test_reflect.py), [grounded answering](../tests/test_grounded_answering.py), [shared engine contracts](../tests/test_shared_engine_contract.py), [consolidation corroboration](../tests/test_consolidation_external_corroboration.py), [working-memory retrieval](../tests/test_working_memory_retrieval.py), [prospective-memory security](../tests/test_prospective_memory_security.py), and [memory-plane isolation](../tests/test_memory_plane_data_only_security.py). Extend these with focused behavioral tests rather than duplicate implementation assertions.

Target scenarios: deletion while synthesis is in flight; source correction after retrieval; identical names in separate tenants; merged entity rollback; duplicate evidence from one underlying source; negated and numerical near-twins; broad-year queries with dense recent history; absent/invalid timezone; malformed provider citation IDs; unsupported visual input; stale mental model after source retraction; and explicit no-answer questions.
