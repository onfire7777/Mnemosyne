# Mnemosyne engineering review — 2026-09-04

This review reproduced and repaired defects in memory privacy, persistence,
tenant isolation, background jobs, development-benchmark transport, and the
standalone embedding HTTP service. Each behavioral fix has a regression that
failed before the change. Separate agents reviewed the fixes.

Baseline: `origin/main@e29ea51bf1b76d6fa50958eaf0bdde4054373642` (PR #134).
Working branch: `codex/memory-runtime-hardening`.

### Broader failure classification

These are failure groups, not 185 independent application bugs:

- Production renderer/TLS and eval-window tests need Bash, OpenSSL, or macOS
  facilities unavailable on this host. Many provider fixtures execute POSIX
  shebang scripts or use POSIX command quoting; packaged CLI fixtures also
  expect `mneme` rather than Windows' `mneme.exe`.
- The durable deletion ledger explicitly requires POSIX `fcntl` locking;
  other checks require FIFOs, Unix sockets, POSIX permission modes, or symlink
  privileges. Those contracts were not weakened to pass on Windows.
- Minimal-environment CLI fixtures omit Windows system variables, causing
  `_overlapped` initialization errors. Some planning/graph fixtures also assume
  POSIX paths.
- Canonical-byte fixture mismatches, oversized test IDs, and clock/order
  assumptions were corrected and rechecked as listed above. The real parametric
  long-path defect was reproduced and fixed in production code.

Full Linux/macOS, permission, and deployment validation remains outstanding.

## Limits and compatibility

- Already mixed-tenant SQLite files now fail closed. No existing user databases
  were migrated or repaired. Legacy untagged journal rows cannot establish
  historical tenant ownership. Existing filename mappings are preserved, so a
  colliding tenant ID is rejected rather than assigned a new storage path.
- The engine still commits its ledger before its journal, as designed. Actual
  disk failure after ledger commit remains a journal-divergence/recovery event;
  the ownership lock closes admission races rather than changing this order.
- Redaction covers content and the metadata payload. Existing envelope fields
  such as task identifiers retain their established semantics.
- PostgreSQL and Python still differ for exotic numeric strings outside the
  tested forms, notably Unicode digits and exponents beyond PostgreSQL's
  numeric parser range. Common queue priority values and huge JSON integers
  have explicit regression coverage.
- Rust and provider boundaries received static review, but no Rust build was
  available. Full PostgreSQL memory-engine, native acceleration, deployment,
  and measured hardware validation are outside the executed checks.
- Windows UNC prefix conversion is covered, but no live network share was
  available for an end-to-end UNC artifact test.
- Committed benchmark fixtures, score artifacts, publication flags, and
  admission states are unchanged. Repaired scoring can change newly generated
  results. M02's rejection of empty answerable-hit lists is an explicit approved
  contract, not silently altered by this repair.
